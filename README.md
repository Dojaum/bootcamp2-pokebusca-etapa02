## Descrição

O **PokéBusca** é uma aplicação web que permite pesquisar Pokémon pelo nome ou número e visualizar imagem, número, altura, peso, tipos e habilidades.

Nesta Etapa 02, a aplicação recebeu persistência de dados usando **Supabase/PostgreSQL**. O usuário pode salvar Pokémon favoritos, visualizar os favoritos mesmo depois de fechar o navegador e excluir registros. A aplicação também foi conteinerizada com Docker e publicada no Docker Hub.

## Persistência de dados

### Banco escolhido

Foi utilizado o **Supabase**, que fornece um banco PostgreSQL hospedado.

### Tabela

A aplicação utiliza a tabela `favoritos`:

| Campo | Tipo | Descrição |
|---|---|---|
| `id` | bigint | Identificador do favorito |
| `criado_em` | timestamp | Data e hora da criação |
| `nome_item` | text | Nome do Pokémon |
| `dados_extra` | jsonb | Dados complementares do Pokémon |

O campo `dados_extra` armazena informações como ID, imagem, tipos, altura e peso.

### Operações implementadas

A aplicação implementa as operações necessárias:

- **Create:** botão `Favoritar` insere um Pokémon no banco.
- **Read:** a seção `Meus favoritos` consulta e mostra os registros.
- **Delete:** cada favorito possui o botão `Excluir`.
- **Update:** não foi implementado nesta etapa, pois é bônus.

Os dados não dependem do `localStorage`. Eles ficam armazenados no PostgreSQL do Supabase e continuam disponíveis depois que o navegador é fechado.

### RLS

A tabela possui Row Level Security (RLS) habilitado. Foram criadas políticas públicas para permitir `SELECT`, `INSERT` e `DELETE` usando a chave `anon`.

**Limitação conhecida:** nesta atividade as políticas públicas foram utilizadas para atender ao requisito da etapa. Em uma aplicação real, o acesso deveria ser protegido por autenticação e regras específicas por usuário.

## Configuração do Supabase

No arquivo `script.js`, devem ser preenchidos:

```javascript
const SUPABASE_URL = "URL_DO_PROJETO";
const SUPABASE_ANON_KEY = "CHAVE_ANON_PUBLIC";
```

A URL e a chave podem ser encontradas em **Supabase → Project Settings → API**.

## Como criar a tabela

No SQL Editor do Supabase, foi utilizado:

```sql
create table public.favoritos (
  id bigint generated by default as identity primary key,
  criado_em timestamp with time zone default now(),
  nome_item text not null,
  dados_extra jsonb
);

alter table public.favoritos enable row level security;

create policy "Permitir leitura publica"
on public.favoritos
for select
to anon
using (true);

create policy "Permitir insercao publica"
on public.favoritos
for insert
to anon
with check (true);

create policy "Permitir exclusao publica"
on public.favoritos
for delete
to anon
using (true);
```

## SQ1 — .dockerignore

Foi criado o arquivo `.dockerignore` para impedir que arquivos desnecessários, como `.git`, `README.md`, arquivos `.zip`, rascunhos e configurações do VS Code sejam enviados para o contexto do build.

Isso reduz a quantidade de arquivos processados pelo Docker, deixando o build mais rápido e evitando colocar conteúdo desnecessário na imagem.

### Se eu tivesse 100 containers, como gerenciaria?

Se a aplicação tivesse 100 containers, fazer o gerenciamento manualmente seria trabalhoso. O Kubernetes poderia ser utilizado para orquestrar esses containers. Em um cluster Kubernetes existem máquinas responsáveis por executar as cargas de trabalho, enquanto os Pods representam as unidades básicas onde os containers são executados. Para manter várias cópias da aplicação, seriam configuradas réplicas. Dessa forma, o Kubernetes pode distribuir os Pods, substituir instâncias que apresentarem problemas e ajustar a quantidade de réplicas conforme a configuração do sistema.
